## 状态用语

- **已实现**：代码存在且可以指出实现入口；不自动表示已部署。
- **已部署**：某次发布已加载到服务；必须注明验证边界，实时状态以服务查询为准。
- **已验证**：明确是单元/mock/集成测试，还是实际渠道端到端验证；不互相替代。
- **待实现/待验证**：当前没有实现，或缺少相应验证证据，不能写成保证。
- **历史记录**：仅解释当时的选择和候选方案，不覆盖现行文档。

## 更新约定

1. 改动行为时同步修改当前架构的相关段落和对应专项文档；不要只在末尾追加一段相反的“最新说明”。
2. 命令变更同步 src/help.rs、命令参考和 README 汇总。新增默认值同时检查示例、回退方式及旧配置兼容说明。
3. 已被替代的方案归档到 history，保留原入口的跳转说明；移动文档时修复相对链接。
4. 文档中的数字、状态和限制必须能对应代码或明确标注的验收记录。不要把旧测试总数当作当前持续保证。
5. 合并前检查 Markdown 相对链接、git diff --check，以及文档改动是否与本次代码范围一致。纯文档修改无需重启服务。
