# Agent 模板与实例设计

状态：用户已确认固定 Bot 归属及可配置新建模板；以下配置格式、管理入口、版本规则为建议，尚未批准实现。

最新字段精简与主会话动态配置见 [模板最小字段](template-fields.md)。首个引擎已确定 Codex；下文较完整的 schema 例子是早期高级候选，不要求用户填写所有字段。

## 1. 已确认关系

一个 Bot 管理多个 Agent 实例，每个实例只能属于一个 Bot。AgentTemplate 可复用来创建多个独立实例，包括不同 Bot 下的实例。实例拥有各自的会话、任务队列与运行状态；模板不包含运行状态。无需 BotAgentBinding 多对多对象。

## 2. 建议配置入口

首版建议用 YAML 文件编写模板，通过模板管理接口执行校验、注册与查询。文件便于手工编辑、复制和版本管理；校验通过后登记的不可变版本才可用于实例化，磁盘文件变化不自动影响运行实例。注册接口不要求单独部署服务。

建议管理命令表达 validate、register、list、show、create-agent 等操作；实际命令名和 CLI 名称尚未确定。聊天入口以后可以调用同一管理接口，引导填写模板或从模板创建 Agent，无需另建一套配置语义。首版是否需要聊天创建模板待确认。

模板配置示例（仅说明结构，字段名及引擎适配器标识待定）：

```yaml
schema_version: 1
id: code-reviewer
version: 1
description: 阅读项目代码并给出审查意见
role: |
  分析代码中的正确性、可维护性与测试覆盖问题。
engine:
  adapter: selected-engine
skills:
  - code-review
functions:
  - review-code
capability_requirements:
  required:
    - workspace.read
  optional: []
context_requirements:
  on_start: []
  on_action:
    review-code:
      - project.reference
overridable_fields:
  - engine.model
```

模型名称、技能和功能 ID 必须来自已注册且兼容的目录；示例不代表这些组件已经存在。YAML 安全解析，拒绝未知字段、自定义执行标签、远程 include 及任意命令插值。首版不支持模板继承链、脚本钩子或自动安装依赖。

## 3. 模板、实例与 Bot 的字段边界

| 位置 | 内容 |
| --- | --- |
| 模板 | 角色、技能引用、引擎默认配置、功能、能力需求、按阶段声明的上下文需求、可覆盖字段 |
| 实例 | agent_id、固定 bot_id、实例名、模板版本与配置快照、允许的覆盖项、工作区引用、实际能力配置 |
| Bot | 入口权限、身份来源、平台能力、业务信息提供器与回复规则 |
| 运行时 | 已核验请求者、任务能力、当前会话、真实凭据句柄、回复目标 |

模板不保存平台凭据、会话记录、任务、用户身份、Bot ID 或机器绝对工作路径。项目路径由实例绑定；模板可声明“需要工作区”这样的需求。Agent 默认语言等可给出非安全默认值；动态身份和权限始终由运行时确定，不能被模板默认值覆盖。

模板的能力声明是需求而非授权。例如模板要求 workspace.write，创建者仍须有创建实例和授权该工作区的权限，Bot 策略也必须允许。必需能力不可满足时拒绝创建并解释缺项；可选能力缺失时仅按明确的功能依赖禁用相关功能。

## 4. 新建实例流程

1. 有权限的创建者选择目标 Bot、可见模板及精确版本，填写实例名、工作区与允许覆盖项。
2. 校验模板 schema、技能/引擎/功能兼容性与引用可访问性；不在此过程中自动安装或执行模板所引用的内容。
3. 校验创建者管理权限、Bot 策略、实例请求能力和工作区访问权，并检查所需 Bot 信息是否有可用提供器；延迟读取的业务数据无需提前全部获取。
4. 返回解析后的配置、能力范围与缺失项以便审阅；已有充分授权时可直接创建，不强制增加第二轮确认。
5. 原子保存新 agent_id、bot_id、模板版本/摘要、覆盖项、最终配置快照和审计来源，分配独立状态。
6. Worker 在实际运行时按既定启动策略创建。创建 Agent 不自动赋予发送外部消息、发布或迁移数据的权限。

实际运行仍要进行任务级和动作级授权；创建时通过校验不代表永久授权。Bot Context 渐进披露、Conversation Context 由 Agent 管理的原则保持不变。

## 5. 版本与生命周期

模板保存为 template_id + version 的不可变版本，schema_version 表示格式版本。相同版本不同内容拒绝注册，相同内容重复注册可幂等返回。运行实例固定使用已选版本的解析快照，模板更新只产生新版本。

模板更新不自动升级实例。Agent 实例自身可采用 config_revision，新协作读取最新生效配置，已有协作固定创建时配置版本。System prompt 编辑入口与首版优先级仍待定，不要求为每次配置修改新建 Agent，也不做运行中热替换，详见 [临时协作会话](collaboration-sessions.md)。

模板可归档以禁止新建实例；已创建实例不因归档被删除。归档不是安全撤权，紧急停用通过运行时策略和 Agent 停用机制执行。保留被实例引用的版本与摘要以供审计。

模板访问权与 Bot 管理权分开：能读取模板不等于能在任意 Bot 下创建 Agent。首版建议提供私有和实例部署内显式共享两种可见范围，不建设公共模板市场。模板拥有者与分享权限的具体规则仍待确认。

## 6. 最小验收场景

- 同一模板创建的不同 Bot 实例具有不同 agent_id，会话和队列独立。
- 改动模板文件或发布新版本不改变现有实例快照。
- 模板请求的能力不能越过 Bot、用户或工作区授权。
- 缺失技能、未知覆盖项和不兼容引擎被明确拒绝。
- Agent 不能改变 bot_id 迁移归属，也不能借模板访问另一实例的私有信息。
- 模板归档影响新建，既有任务及其版本溯源保持完整。

仍需确认：YAML/管理 CLI 是否作为首版入口、是否同时支持聊天创建、允许覆盖字段清单、模板分享权限，以及首版技能和功能目录。
