# 临时协作会话：已确认方案

状态：用户已确认本方案的会话语义，仍为架构设计阶段，不代表开始实现。引擎适配、TTL、并发限额与更新入口等细节待定。

## 1. 首次调用与多轮续接

已确认交互为请求方 A → 被查询方 B 的 query/response。B 应对请求给出结果，A 决定展示、使用、继续追问或结束；不要求 A 回复每个答案。新的追问有新 request_id，但复用 collaboration_id。B 答完即可空闲，A 不回应不会触发新的工作。结果由 A 通过其所属 Bot 向用户呈现，运行时投递确认不属于模型对话。

一次新的 Agent 协作创建目标 Agent 下的临时协作会话，以 collaboration_id 标识。创建时读取目标 Agent 当前有效配置快照，包括 system prompt、角色、引擎/模型默认值、技能和工具配置、Bot 与工作区引用；不复制目标 Agent 的对话历史、摘要、未完成任务或正在执行的工具调用，也不复制凭据。

目标 Agent 的永久身份和 bot_id 不变，临时会话不是新的注册 Agent。每个会话有独立的 engine session_ref、上下文、执行记录和资源状态。当前动作权限由运行时重新验证，不从配置快照获得永久授权。

同一协作的追问携带同一 collaboration_id，复用该会话自己最新的上下文。独立工作创建新的 collaboration_id，不能只按调用方+目标 Agent 自动复用。每轮消息有唯一 message_id/request_id，与整段协作 ID 分开。会话标识不是授权凭据，续接时校验调用方、原始主体、来源任务及有效授权；新 Task 若要续接旧协作需由运行时显式建立关联，不能凭 ID 自动读取历史。

默认结果回调用方，由调用方汇总给用户；不把临时会话完整历史自动合并进目标 Agent 主会话。临时会话按需读取目标 Bot 的信息，仍使用目标 Bot 身份执行。

## 2. 配置版本

模板是创建实例的初始配置，Agent 实例可以拥有自己的 config_revision。临时会话固定创建时的配置版本，新会话读取最新生效版本；已有协作后续轮次继续原版本，不在多轮中途自动更换角色或 system prompt。

System prompt 动态修改的候选方向是发布新 config_revision；不意味着修改旧模板或对运行中引擎热替换。是否首版提供编辑入口、谁能编辑及主用户会话何时应用新配置仍待确认。权限撤销、停用和工具访问策略独立于配置版本，实时检查。

## 3. 并发与消息

同一会话只允许一个活动执行者，保证上下文顺序；不同协作会话可以并行，但受 Agent/Bot/全局限额约束。共享工作区写入仍需 worktree 或资源锁，不因上下文独立而自动安全。

首次协作采用独立会话，不取决于主会话是否忙。会话忙时后续消息仍归该会话输入通道，消息顺序及 steer/排队规则待定。用户希望通过 Bot 发来的消息直接 steer；这项与引擎能力、正在执行工具的停止机制尚需确认，不能把“收到输入”等同于“已立即应用指导”。

逻辑会话并发不要求某一种进程布局。每 Agent 一个管理 Worker 下调度独立会话执行器、或者按活动会话建进程，需按引擎独立会话支持和隔离需求进一步选型。旧草案每 Agent 全局单执行槽不再作为已收敛方案。

## 4. 回收与恢复

每轮执行完成不等于整段协作关闭。等待后续追问且无在途执行时可以进入 idle；同一协作新消息刷新其活动时间。运行中、等待工具、等待子任务或等待明确用户输入的会话，不能按普通空闲会话直接删除。

回收分两层：释放 Worker/引擎运行资源；按单独保留规则删除会话上下文。结果、审计和必要产物使用独立保留策略。TTL 与“完成/关闭/过期”的具体 API 待定。

运行资源释放而会话记录仍在时，优先使用引擎原生恢复；不支持时，只有在记录足够且策略允许时明确采用摘要重建，不声称完全恢复原始内部状态。会话记录已删除则返回已过期；新工作创建新 collaboration_id，可引用仍获授权的保留结果，不静默伪装为原会话。

回收和新消息到达必须原子协调：删除前检查会话版本、活动执行及待处理消息；已接收的消息不能被回收器静默丢弃。实现方式与时长待定。

## 5. 仍待定的关联议题

- 全通：用户希望 Agent 间全通，旧的逐对调用白名单建议正在重新评估；全通信任范围、调用授权与结果可见性尚未定稿。
- Steer：用户希望用户输入直接插入，具体引擎是否支持、时机与失败降级需核实。
- 配置更新：新会话使用新版本、旧协作固定版本已收敛；system prompt 编辑功能的首版优先级尚未确定。
- TTL、并发/费用预算、同会话忙时追问语义、隔离与恢复参数待确认。

## 6. 后续验收设计

新协作没有目标主会话历史；多轮续接能记得自己的前轮内容；独立协作不串上下文；修改目标配置只影响新会话；撤权对旧版本会话生效；伪造 collaboration_id 不可续接；重复消息不重复执行；回收后可明确恢复或报告过期；回收与消息并发不丢已接收消息。
