# 渐进回复与飞书流式卡片

实现完成；真实飞书卡片发收验收尚未进行。

## 共用流程

引擎 agentMessage 开始、增量、完成事件统一进入 Collector，以任务 ID、generation、消息 ID 区分输出，只展示 commentary/final_answer。缺少 phase 时等完整消息到达。增量不单独发送微信消息。

Collector 随 250ms 任务 tick 刷新投影，完整消息立即刷新。事务验证代次与 running 状态。reply_desired 保存最新内容，reply_transport 保存网络检查点，网络响应不覆盖生成侧状态。

普通投递与卡片 worker 独立；卡片每轮约 1 秒更新，最多并行 4 个任务，同任务顺序执行。进度和答案使用独立卡片。每次 CardKit 更新提交全量文本。

答案和进度卡片均不显示标题，只显示正文。卡片初始正文为实际已生成内容，摘要取正文前 100 个字符（空白合并，超长加省略号）。正文开头变化时通过持久化 Summary 操作更新摘要，共用序号、UUID 与重试检查点；不再固定显示“正在处理”。

## 配置

数据目录 reply-streaming.json 按 Bot 设置 off、progress 或 card，缺省为 off。示例：{"webot":"progress","kick":"card"}。

- progress：微信/飞书可用，完整进度通过现有持久化消息队列发送，最终答案保持原流程。
- card：仅飞书，需要 cardkit:card:write 及 IM 发送权限。
- off：保持结束后一次性发送；已有卡片尽力关闭，最终结果通过普通消息兜底。

配置文件用临时文件加原子替换。新任务按启动时模式收集；卡片 worker 每轮读取开关。代码上线需重启服务，切换开关不需重启。

## 检查点与故障

创建后先保存 card_id；发送前持久化 UUID。更新前持久化文本、递增序号及 UUID，重启后复用同一操作，成功再清除。创建响应丢失可能留下未发送的孤立卡片。

连续失败三次后降级普通最终消息；超过 24KB 或关闭开关时尽力关闭卡片后降级。兜底发送时，如果卡片确认送达内容是完整结果的精确前缀，只发送尚未送达的后缀；不按相似度猜测或删改任务原始结果。兜底消息在发送前持久化，重试使用同一内容。全文已确认送达但关闭失败时也不重发全文，卡片关闭状态与内容送达状态分别记录。内容被改写而无法精确匹配时保留完整兜底，防止丢失信息。取消/失败保留普通通知。记录失败 API 数字错误码，不记录凭据或接口原文。外部接口结果不确定时不承诺绝对恰好一次。

任务终止或 generation 变化后旧卡片收尾，旧 Collector 不再写入。启动时原 recover 将旧运行任务标记 interrupted，卡片 worker 据此处理。

飞书文本更新明确返回 200850/300309 时，在同一卡片重新开启流式模式，再以更高序号更新；每次更新最多一次重新开启。open 操作与文本操作都持久化 UUID/序号，响应未知或重启后重试原操作。未实现未经证实的定时提前续期。取消、旧代次、关闭功能后只收尾，不续开；旧 failed 卡片不自动重放。详见 [超时恢复](card-stream-reopen-plan.md)。

## 验收

本地假 lark-cli 测试覆盖增量拼接、消息阶段、微信完整进度去重、卡片创建/原消息回复/更新/关闭、最终答案去重、重启复用 pending 操作、过时代次拒绝、连续失败降级及取消收尾。不向真实用户外发。

真实验收需指定测试会话后检查客户端效果、真实更新幂等和限流。在真实验证前不推广其他 Bot 的 card 模式，回退将 Bot 改为 off。

## 命令回复

微信与飞书共用命令投递规则。/sh、/retry、/ask、/compact、媒体解析/重试和 /bot add 在持久化记录确认后续结果有回复目标时，不发送受理回执。错误、缓存命中、查询和同步配置操作仍立即回复；Bot 添加保留扫码/授权提示。重试任务将最终结果绑定到本次命令的回复目标。

/cancel 和强制停用 Agent 使用持久化完成记录，取消根任务及其子任务，保留执行结果历史，抑制这些任务各自的结束消息，全部收尾后发一条汇总。已有流式卡片只关闭，避免取消后新建或重发正文。服务重启后继续完成汇总；Bot 添加中断也会发送最终通知。/compact 完成或失败时回复一次。

## 完成后的折叠

生成期间保持现有流式正文。正常关闭流式模式后，过程卡片显示终态（如“已完成”）并在“展开过程”中保存完整过程；答案超过 300 个 Unicode 字符或 8 行时，保留完整且可独立显示的开头段落，余下 Markdown 放入默认收起的面板，正文不重复。代码块、表格或无法安全拆分的开头整段放入面板。折叠入口使用 header.position=bottom，文案为“展开 / 折叠内容”，展开后位于全文末尾。聊天列表摘要仍取正文真实开头。短答案直接显示。保留过程/答案两张卡片，卡片本身无标题。

折叠使用 CardKit 全量更新接口，作为持久化 Layout 操作记录固定 JSON、sequence 和 UUID。关闭成功即已完成正文投递；折叠最多重试三次，失败保留原展开卡片，不触发普通文本补发。历史 closed 记录默认无 layout_pending，不重放、不批量修改历史卡片。客户端展开/收起不触发模型请求，完成后不再持续刷新卡片。

未配置的飞书 Bot 默认使用 card，新增 Bot 无需逐个登记；已有显式 off/progress/card 配置优先，微信默认仍为 off。

## 聊天配置

/stream 查看当前 Bot 生效模式与来源；/stream card、/stream progress、/stream off 设置当前 Bot；/stream default 删除覆盖项并恢复渠道默认（飞书 card，微信 off）。支持 /stream help、/help stream 和 -r 原始结果。微信不允许 card。所有操作沿用聊天 owner 检查，只操作路由 Agent 所属 Bot，命令只回复一次且不创建 Agent 任务。

写入 reply-streaming.json 时使用跨进程文件锁、临时文件和原子 rename，保留其他 Bot 配置；非法 JSON 明确报错，不覆盖。新任务创建 Collector 时读取模式，卡片 worker 也检查当前模式，所以切换离开 card 会关闭已有卡片并走最终投递规则。正在运行的 progress Collector 不追溯撤销已发进度。
