# 独立监督与恢复方案

日期：2026-10-14。状态：**待实现、待部署、待演练**。本页定义目标与验收条件，不新增可执行命令，不表示系统已经具有自动恢复能力。现有能力见[环境操作](environments.md)。

## 目标与边界

prod 承载主要使用，dev 是开发和修复入口。计划变更必须保留一个已验证可用的实例；dev 升级时，恢复步骤不能依赖正在停止的 dev Agent。独立 supervisor 应在业务进程退出或升级任务中断后继续执行检查与恢复。

supervisor 存活不等于业务可用或数据必然可恢复。磁盘故障、凭据撤销、模型服务不可达或不兼容数据库迁移都可能阻断恢复；同机方案也不能覆盖断电和整机故障。需要覆盖整机故障时，再增加异机监控、备份和备用实例。

## 目标结构

```text
macOS launchd
  └─ 独立 supervisor（独立版本、状态、日志和本地管理入口）
       ├─ dev：固定发布文件 + 独立数据目录
       └─ prod：固定发布文件 + 独立数据目录
```

supervisor 是小型确定性程序，基础检查、启动和回退不依赖模型、飞书或 dev/prod 进程。Agent 负责分析问题、准备变更和解释结果。监督程序使用独立固定路径，不能随普通应用发布一起更新；其依赖和手动救援入口也需固定。

launchd 安装方式需实现时选择并说明：用户 LaunchAgent 通常依赖登录会话，不应宣称注销后仍可用；系统 LaunchDaemon 与用户 Keychain、环境和凭据访问的兼容性需要单独验证。

## 运维契约

| 场景 | 目标处理方式 |
| --- | --- |
| 进程退出 | 校验无旧进程/锁占用，再有限次数启动登记版本 |
| 心跳过期、进程仍在 | 收集诊断，区分忙碌和失去响应；不能直接启动第二份监听 |
| 模型或渠道不可用 | 标记依赖故障，退避检查；不能靠无限重启或反复回滚解决 |
| 版本启动失败 | 数据兼容且满足回退条件时切换已验证产物；失败达到阈值后停止自动操作 |
| 一边异常 | 暂停另一边的非必要变更，保留最后可用入口 |
| 两边异常 | 按故障类型恢复，优先恢复 dev 维护入口，保留本地诊断通道 |
| 计划停服或排空 | 尊重维护状态，不与发布流程竞争拉起服务 |

健康状态至少区分进程、服务响应、发布身份、渠道和模型依赖。记录观察时间与失败原因，避免把旧健康记录当作实时证据。模型探针需控制频率和费用，外部测试消息需有授权。

## 发布状态与恢复

使用持久化操作记录、跨实例发布互斥和幂等步骤。建议流程为：预检查 → 排空 → 停止 → 备份 → 选择版本 → 启动 → 验证 → 完成。记录旧/新发布、兼容性、备份范围和阶段结果，复用或协调现有 deployments 记录及锁，避免形成两套互相竞争的服务管理器。

发布必须串行：另一个实例不健康则不进入计划停服；当前实例验证通过后才允许下一实例变更。当前 Agent 提交的自升级请求需先被外部监督流程持久化接收，让发起任务结束，再开始排空。

排空超时保留诊断和明确维护状态，不默认为强杀；监督程序意外退出后应从记录判断阶段，不能无条件重做迁移或重发消息。程序回退不得隐式恢复旧数据库或重放外部投递。保留已验证版本的产物与依赖，schema 不兼容时进入人工处理。

supervisor 自升级另设维护流程与固定救援工具，不与 dev/prod 一起升级。手动救援先确认 supervisor 是否接管及锁状态，避免自动恢复与人工启动冲突。

## 验收条件

先在临时实例、local Bot 和 mock 服务中做故障注入，不向正式 Bot 注入故障。至少覆盖：

- dev 或 prod 单独退出后能恢复，另一实例持续服务，无重复平台监听。
- 当前 Agent 发起 dev 升级后退出，监督流程仍能完成升级或兼容回退。
- 排空被活动任务阻塞时报告原因，不自排空死锁、不强制停止最后可用实例。
- 新版本无法启动、发布中断、supervisor 被重启时，能依据持久化状态继续或停止在可诊断阶段。
- 模型/渠道不可达时限制重试；连续失败进入停止自动恢复的状态，避免重启循环。
- 维护停服不被自动拉起，自动管理和手动恢复不会竞争。
- 数据不兼容、磁盘不足和备份失败时，在危险变更前拒绝继续。
- launchd 在选定登录/开机场景中有效；真实模型和渠道恢复需单独验收。

完成后更新本文状态、实施文档和真实验证记录，不能仅凭 mock 测试宣称完整可恢复。
