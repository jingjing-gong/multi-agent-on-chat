# 聊天语音气泡实施规划

2026-10-02。状态：第一阶段已实现；用户明确第二阶段暂缓。第一阶段支持微信随消息提供的转写文本，无文本时提示重发或转文字；不包含本地/远程音频转写。真实微信语音气泡端到端验收仍待用户消息验证。

验证：`cargo test --all-targets` 107 项通过；`cargo clippy --all-targets -- -D warnings` 通过。已重建 mac-cli 并在无活跃任务时重启后台服务，启动恢复记录 interrupted=0。

## 已核实的基础

- 实施前 mac 的 `src/channels.rs::parse_wechat_updates` 仅读取 `text_item.text`。现在会按 item 顺序读取 `voice_item.text`，跳过未完成消息，语音不再作为待下载附件阻塞输入。缺失 message_state 的兼容事件沿用原处理，显式非完成状态不处理。
- 旧项目 `codex-on-wechat/src/channels/wechat.py` 已将 `voice_item.text` 作为用户输入，且有 `tests/test_wechat_audio_ingress.py` 覆盖顺序、重复投递和缺少转写的情况。该字段是否存在取决于实际微信事件，不能假设每条语音都提供。
- mac 已有附件下载/解密、持久化入站队列、Bot/会话隔离，以及带重试、取消和结果资产的解析任务系统。音频解析尚未实现。
- 本机已有 ffmpeg/ffprobe；这不代表已支持微信 SILK，需用实际文件验证。

## 第一阶段：微信已有转写立即可用

1. 按消息 item 顺序读取 `voice_item.text`。非空转写与打字输入使用相同的会话、任务指导和命令路由规则，不额外要求确认。已有命令权限与确认规则继续适用。
2. 有转写的语音不依赖音频下载才能提交，也不重复追加语音附件占位。图文混合消息保留其他附件和原始顺序。保留语音来源及消息关联信息用于排查，不在普通日志记录全文。
3. 空白或缺失转写的纯语音返回明确提示，不创建只有附件占位的空任务。混合消息仍处理可用文本，并提示哪些语音尚未识别。
4. 沿用入站去重、owner 校验、Bot/会话隔离及活跃任务处理逻辑，避免引入第二条提交路径。

验收：有转写的语音能启动或指导任务；同一事件重复到达只处理一次；语音加文字保持顺序；语音加图片不丢附件；无转写纯语音有提示且不空跑；完成消息与流式/未完成消息不会重复执行。参考旧项目回归用例，但按 mac 的实际协议及事件生命周期实现。

## 第二阶段：无转写语音自动识别

1. 在现有媒体解析系统增加 `transcribe`，复用持久化任务、结果资产和作用域校验，不让 Agent 模型 worker 等待音频处理。入站事件等待准备完成后只提交一次最终输入；取消/重试/重启不得导致旧结果重复提交。具体状态及提交事务需在实施时与现有 ingress 去重事务对齐。
2. 下载解密后通过魔数及 ffprobe 检测格式；ffmpeg 规范化为转写后端所需格式。微信 SILK 若不受本机 ffmpeg 支持，增加经过验证的解码器；缺少解码器时报告明确原因。不要仅靠扩展名判断格式。
3. 定义独立的 Transcriber 接口和配置，包含后端、模型、凭据引用、超时及大小/时长限制。转写模型与聊天 profile 分开配置，不能假设聊天 provider 支持转写。优先复用已验证的转写服务；若没有合适服务，再选择本地 Whisper 兼容后端并实测中文及资源消耗。实施前明确一个实际后端，不能只交付接口。
4. 微信平台已有非空转写时优先使用；没有文本才执行转写。飞书语音气泡使用同一后端，补齐其音频资源下载及消息归一化。普通录音文件先保留为附件，用户明确要求转写时调用解析能力，不默认把录音内容当作指令。
5. 建议首版自动转写上限为 5 分钟、20 MiB，后端超时 120 秒；并发及归一化输出大小有上限。短语音直接继续对话，较慢任务只发送一次处理中提示。数值作为初始配置，按真实后端验收调整。
6. 结果记录文本、后端/模型版本和来源；时间戳仅在后端提供时保存。缓存包含音频哈希、Bot/会话范围、后端版本及选项。识别失败、空结果、超限、鉴权失败、服务不可达分别提示；不得编造内容。

## 验证与上线

- 单元/集成：文本归一化、混合顺序、空转写、权限隔离、幂等、解码失败、超时/取消、服务重启恢复、转写结果只提交一次。
- 后端契约：本地 mock 覆盖成功、401、限流、超时、空文本和格式错误；只对临时错误有限重试。凭据不写入日志、错误消息或结果资产。
- 真实验收：用户在微信发送已知内容的中文语音；第一阶段验证平台转写路径，第二阶段额外验证无平台转写路径。飞书独立验收。模拟事件不能代替真实气泡测试。
- 上线顺序：先交付第一阶段；第二阶段在一个 Bot 验证后推广。发布前检查活跃任务，空闲时重启。可独立关闭自动转写，回退为明确提示，不影响文本和图片处理。

本规划不包含语音回复、实时语音通话、说话人分离或长会议录音总结。
